# 報價匯入資料驗證 Implementation Plan

相關文件：[[2026-08-24_報價匯入資料驗證_SPEC]] · [[2026-08-24_報價匯入資料驗證_SDD]] · [[2026-08-24_報價匯入資料驗證_CHECK]]

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓 URL 與 JSON 檔案匯入都經過同一個嚴格、可回報欄位錯誤且相容舊格式的 parser。

**Architecture:** 在 `src/domain/quotationValidation.ts` 集中處理 JSON 大小、語法、資料結構、欄位型別與舊格式預設值；`App.tsx` 與 `QuotationForm.tsx` 只負責輸入解碼、呼叫 parser、成功更新狀態或失敗顯示錯誤。parser 以 `unknown` 輸入並建立全新的 `QuotationData`，不直接信任或展開匯入物件。

**Tech Stack:** React 19、TypeScript、Vitest、原生 `JSON.parse`，不新增第三方依賴。

### Task 2: 實作集中式 parser

**Files:**
- Create: `src/domain/quotationValidation.ts`
- Test: `src/domain/quotationValidation.test.ts`

- [ ] **Step 1: 建立結果型別與常數**

實作 `ValidationError`、`ValidationResult<T>`、`MAX_JSON_BYTES = 1024 * 1024`、陣列／文字上限與 `parseQuotationData`／`parseQuotationJson` export。

- [ ] **Step 2: 實作 primitive helpers**

建立 `isRecord`、`readString`、`readOptionalString`、`readEnum`、`readNonNegativeNumberString` 與 `readArray`；缺少允許的舊欄位套用預設值，欄位存在但型別錯誤必須加入錯誤，不得 `String(value)` 強制轉換。

- [ ] **Step 3: 實作 Party、item、booklet job／part parser**

逐欄位建立新物件；`partyB` 缺少時使用 `createEmptyPartyB()`；`items`、`bookletJobs`、`parts` 驗證陣列型別與上限；`taxType` 僅接受 `exclude`／`include`。

- [ ] **Step 4: 實作 QuotationData parser**

驗證 `quotationType`，依類型讀取 `items` 與 `bookletJobs`，其餘欄位補空字串，回傳只包含 `QuotationData` 定義欄位的新物件；錯誤時回傳完整 errors 陣列。

- [ ] **Step 5: 實作 JSON parser**

以 UTF-8 字串的 byte length 檢查 1 MB 上限，包住 `JSON.parse`，再委派 `parseQuotationData`；所有失敗都回傳 `success: false`。

- [ ] **Step 6: 執行 GREEN 測試**

Run: `npm.cmd test -- --run src/domain/quotationValidation.test.ts`

Expected: 新增 parser 測試全部通過。
