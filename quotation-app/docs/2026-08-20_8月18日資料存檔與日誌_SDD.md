# 8月18日資料存檔與日誌設計

相關文件：[[2026-08-20_8月18日資料存檔與日誌_SPEC]] · [[2026-08-20_8月18日資料存檔與日誌_PLAN]] · [[2026-08-20_8月18日資料存檔與日誌_CHECK]]

## 架構與元件責任

- Git 歷史：作為 8/18 已保存內容、時間與變更範圍的主要證據。
- 備份 tag：作為本次補寫文件前的可還原點。
- `3_Daily_估價單系統日誌/2026-08-18.md`：提供當日工作摘要、Git 存檔、驗證與產出索引。
- `quotation-app/docs/` 四文件：記錄本次補存檔與補日誌工作的需求、方法、步驟及驗證。
- [[2026-08-18_乙方資料_CHECK]]：保留原始功能驗證細節，不在新日誌中重複展開全部測試歷程。

## 資料模型

本次沒有新增應用程式資料模型。文件採以下欄位：

- `date`：Asia/Taipei 日期。
- `status`：文件狀態。
- `tags`：專案與文件類型。
- Git 識別：短 SHA 供閱讀，完整 SHA 用於備份驗證。

## 資料流

1. 讀取專案限定範圍的 `git status` 與 8/18 `git log`。
2. 在修改前建立備份 tag，並以 `git rev-list -n 1` 核對指向。
3. 執行測試、lint、build 與列印版面檢查。
4. 將可驗證事實寫入 8/18 日誌與本次四文件。
5. 以 Git diff、檔案清單與文件連結檢查確認修改範圍。

## 錯誤處理

- 若專案範圍有未提交內容，停止整體提交並改用限定範圍備份。
- 若備份 tag 建立失敗，不進行檔案修改。
- 若驗證命令失敗，如實記錄於 CHECK，不宣告通過。
- 若 Obsidian CLI 不可用，改以檔案內容、frontmatter 與 wikilink 靜態檢查驗證。

## 測試設計

- Git：確認備份 tag 與 SHA 一致。
- 文件：確認五個新檔存在、UTF-8 可讀、四文件互鏈且沒有未完成佔位內容。
- 應用程式：執行完整 test、lint、build 與列印版面檢查。
- 範圍：確認 Git diff 僅包含日誌及本次四文件。
