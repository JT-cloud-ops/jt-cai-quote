# 報價匯入資料驗證規格

相關文件：[[2026-08-24_報價匯入資料驗證_SDD]] · [[2026-08-24_報價匯入資料驗證_PLAN]] · [[2026-08-24_報價匯入資料驗證_CHECK]]

## 需求

- 為 URL 分享匯入與 JSON 檔案匯入建立共用的資料驗證入口。
- 驗證失敗時採原子拒絕：保留目前報價資料，不更新狀態。
- 接受已知舊格式，對缺少的後增欄位補安全預設值。
- 對錯誤型別、非法結構、非法 enum、非法數字與超過限制的資料提供具體中文錯誤。
- 驗證成功後建立全新的 `QuotationData`，忽略未知欄位。

## 範圍

- 新增 `src/domain/quotationValidation.ts` parser 與測試。
- 調整 `src/App.tsx` 的 URL 匯入流程。
- 調整 `src/components/QuotationForm.tsx` 的 JSON 檔案匯入流程。
- 保留 `normalizeQuotationData` 的舊資料相容責任，但不再以型別強制轉換取代驗證。

## 非目標

- 不新增 Zod 或其他第三方 schema 套件。
- 不改變報價單計算、預覽、列印與 localStorage 儲存格式。
- 不做部分欄位匯入或自動修正非法值。
- 不重新設計匯入 UI；本次維持既有 alert 與輸入控制項流程。

## 契約

```ts
parseQuotationJson(text: string): ValidationResult<QuotationData>
parseQuotationData(input: unknown): ValidationResult<QuotationData>
```

- JSON 原文上限：1 MB。
- `quotationType` 僅接受 `single`、`booklet`、`dept`。
- `items`、`bookletJobs`、每個 job 的 `parts` 上限：100、50、50。
- 一般文字欄位上限 500 字；備註與加工說明上限 5,000 字。
- 數量、單價、手動金額可空白；非空時必須為有限且非負的數字字串。
- `taxType` 僅接受 `exclude`、`include`。
- 缺少已知舊版欄位時補空字串、空陣列或空白 `partyB`；錯誤型別不自動轉換。
- `ValidationError` 必須包含欄位 path 與繁體中文 message。

## 驗收條件

- [x] URL 與檔案匯入共用同一 parser。
- [x] 失敗匯入不呼叫 `setQuotationData` 或 `onChange`。
- [x] 合法新格式與缺少 `partyB` 的舊格式均可匯入。
- [x] 非法資料可顯示具體欄位錯誤。
- [x] parser、兩個入口與回歸測試全部通過。
