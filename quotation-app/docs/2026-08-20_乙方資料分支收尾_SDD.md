# 乙方資料分支收尾設計

相關文件：[[2026-08-20_乙方資料分支收尾_SPEC]] · [[2026-08-20_乙方資料分支收尾_PLAN]] · [[2026-08-20_乙方資料分支收尾_CHECK]]

## 架構與元件責任

- `master`：整合後的唯一主要工作分支，保存乙方資料功能及後續日誌 commit。
- `feat/party-b-data`：已完成且已納入 `master` 的短期功能分支。
- `.worktrees/party-b-data`：功能分支的隔離工作目錄，確認乾淨後由 Git 移除。
- 備份 tag：在文件修改與分支清理前保存可還原的 `master` 指標。
- 本組四文件：保存收尾決策、操作契約與驗證證據。

## 資料模型

本次不更動應用程式資料模型。Git 狀態以以下識別構成：

- 主分支 commit：`master` 的完整 SHA。
- 功能分支 commit：清理前 `feat/party-b-data` 的完整 SHA。
- worktree 路徑：解析後的絕對路徑。
- 備份 tag：可解析至清理前主分支 commit 的標籤。

## 資料流

1. 檢查主專案與功能 worktree 狀態。
2. 確認功能分支是 `master` 的祖先。
3. 建立並驗證清理前備份 tag。
4. 在 `master` 執行 `git merge --ff-only feat/party-b-data`。
5. 執行完整驗證。
6. 驗證 worktree 絕對路徑與乾淨狀態。
7. 依序執行 `git worktree remove`、`git worktree prune`、`git branch -d`。
8. 驗證 worktree 路徑與功能分支均已不存在。

## 錯誤處理

- 若功能分支不是 `master` 的祖先，停止清理並保留 worktree。
- 若整合不是 fast-forward 安全狀態，`--ff-only` 必須拒絕操作。
- 若任何測試或建置失敗，不移除 worktree 或分支。
- 若 worktree 有未提交內容，停止清理。
- 若解析路徑不完全符合預期，停止所有移除操作。
- 若 `git branch -d` 拒絕刪除，不改用 `-D`。

## 測試設計

- Git：祖先關係、HEAD、worktree 清單及分支清單。
- 應用程式：完整 Vitest、ESLint、production build 與列印版面腳本。
- 清理：`Test-Path` 應為 false，`git branch --list` 應無輸出。
- 文件：四份文件位於 `docs/` 根目錄，具 frontmatter 且互相連結。
