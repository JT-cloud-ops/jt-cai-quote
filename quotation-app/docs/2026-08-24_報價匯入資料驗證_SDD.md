# 報價匯入資料驗證設計

相關文件：[[2026-08-24_報價匯入資料驗證_SPEC]] · [[2026-08-24_報價匯入資料驗證_PLAN]] · [[2026-08-24_報價匯入資料驗證_CHECK]]

## 架構與責任

- `quotationValidation.ts`：負責 JSON 解析、大小限制、未知資料驗證、舊格式預設值與乾淨資料建立。
- `App.tsx`：負責 URL base64 解碼、呼叫 parser、成功後切換畫面、失敗後清理 URL 與顯示錯誤。
- `QuotationForm.tsx`：負責讀取檔案文字、呼叫 parser、成功後呼叫 `onChange`、失敗後保留資料並重設 input。
- `partyB.ts`：保留乙方欄位的空白資料建立與既有格式化責任；parser 只重用安全的空白結構，不使用寬鬆 coercion。

## 資料流

1. URL 或檔案入口取得原始文字。
2. `parseQuotationJson` 檢查文字長度並執行 `JSON.parse`。
3. `parseQuotationData` 以 `unknown` 逐層驗證頂層欄位、items、bookletJobs、parts、partyB。
4. 缺少允許的舊欄位時套用預設值；未知欄位捨棄。
5. 回傳 `ValidationResult`。
6. 只有 `success: true` 才更新 React state。

## 錯誤處理

```ts
type ValidationError = { path: string; message: string };
type ValidationResult<T> =
  | { success: true; data: T }
  | { success: false; errors: ValidationError[] };
```

- JSON 語法錯誤：回報「檔案不是有效的 JSON」。
- 大小超限：回報檔案大小與 1 MB 上限。
- 欄位錯誤：列出最多可讀的 path 與繁體中文說明。
- URL 匯入失敗仍清除 `import` 參數，避免重新整理重複觸發。
- 任一錯誤都不得部分套用資料。

## 測試設計

- parser 單元測試：合法三種類型、舊版缺少 partyB、缺少允許欄位、未知欄位忽略。
- parser 單元測試：錯誤 enum、錯誤型別、非法數字、過長字串、超過陣列上限、JSON 超過 1 MB。
- URL 入口測試：成功更新 state、失敗不更新 state 且清理 URL。
- 檔案入口測試：成功呼叫 `onChange`、失敗不呼叫且重設 file input。
- 回歸測試：既有 partyB、preview 與 quotationCalculations 測試維持通過。

## 實作結果

- parser、URL 匯入與檔案匯入均已依本設計接線。
- `formatValidationErrors` 提供兩個入口共用的 path／訊息格式化。
- 未新增第三方依賴；隔離 worktree 的 tsconfig 僅為本機被忽略設定，不納入版本控制。
